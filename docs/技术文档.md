## 1. 作品简介

《第一年》是一个网页上的文字模拟器，界面做成一部手机。

玩家扮演一个刚毕业、来到陌生城市的二十二岁年轻人，兜里八千块，要撑过九十天。九十天里发生十五次遭遇：到站报平安、看房、签合同、面试、假客服来电、征信电话、饭局、搬家、退租。

每一次遭遇，对面都是一个真人扮演者，由大模型即兴演出。他要的东西不一样：良心人想帮你，黑心人想赚你的钱，骗子想要你的身份信息。

作品的目标不是教人防骗，是让人在安全的地方，把那些坑先踩一遍。

## 2. 选题依据

租房、求职、消费纠纷是应届生最集中的踩坑场景，公开报道和投诉平台上案例充分。现有的大多数反诈宣传是单向的：看视频、读提示，看完就忘。

本作品把它变成对话。玩家要自己回话、自己决定信不信、自己承担后果，记忆点比看十分钟宣传片强。

## 3. 界面设计：为什么做成手机

最初的版本是一个聊天窗口，所有人物都在同一个对话框里出现。试玩时最直接的两个问题：人物认不住，剧情接不上。

改成手机界面来解决这两件事：

**人物分进不同的会话。** 九个联系人分五组（家人、朋友、工作、房东·中介、陌生人），每个人有自己的头像、分组标签，名字下面一句话写清他是谁、怎么认识的。中介和老周都是「房东·中介」，但头像、备注、说话方式完全不同，不会混。

**信息分进不同的 App。** 微信装对话，短信装验证码、银行提醒、分期通知，电话装通话记录和整屏来电，备忘录装玩家自己记下的待办，钱包装余额和流水，相册装这一年拍的照片。

这样设计还带来一个真实的细节：假客服那一关，玩家一边和他聊，一边能在短信里看到六位验证码正好落进来。要不要念出去，是玩家自己的选择，不是弹窗提醒。

**每一步回到桌面。** 消息到了，顶部弹出通知条，点一下才进聊天。玩家也可以先翻钱包、翻备忘录，再决定怎么回。回桌面只有一条路：屏幕最下面那条横线，和真手机一样。作品里不设多余的按钮，省下来的位置都留给对话。

### 先登录，再进这一年

打开的第一屏不是剧情，是登录页：输入名字、挑一张头像（八个预设色块，或者传本地图片）。名字立刻出现在对方的话里、聊天气泡旁和「我」那一页；中途可以改，改完刷新也还在（存在浏览器 localStorage，不上传服务器）。

这个设计有个实际好处：玩家从第一秒起就在"做选择"，而不是被动点开始。名字是他自己填的，接下去被人骗、被人劝的时候，代入感比一个匿名的"你"要重。

### 输入框不用反复点

每轮对话结束后界面会重绘，早期的实现会把光标弄丢，玩家每说一句都得点一次输入框。现在把草稿和光标都留在状态里：发完自动回到输入框末尾，接着打字就发。边等回复边打的字也不会被重绘冲掉。

## 4. 系统架构

三层，全部零依赖：

```
浏览器（HTML / CSS / JS，手机界面）
   │  GET  /api/meta
   │  POST /api/talk   /api/settle   /api/review
   ▼
Python 标准库 http.server
   │
   ├── data/events.json    剧本（事件、节拍、坑、结算）
   ├── data/story.json     联系人 + 时间轴 + 短信/待办种子
   ├── data/fallback.json  兜底台词
   └── 大模型接口（可选）
```

没有数据库，没有框架，没有构建步骤。双击 `启动.bat`，或者 `python server.py`，就能跑。

### 四个接口

| 接口 | 作用 | 是否调用模型 |
|---|---|---|
| `GET /api/meta` | 一次取回剧本、联系人、时间轴 | 否 |
| `POST /api/talk` | 拿对手这一轮的一句话 | 是 |
| `POST /api/settle` | 结算玩家的选择，改数值 | 否 |
| `POST /api/review` | 算分、判结局 | 否 |

## 5. 剧情结构

### 时间轴写死在数据里

`story.json` 的 `order` 是十五步，每步写清第几天、几点、哪个事件、找谁，以及一段旁白作为前情。

顺序不随机。上一版是随机抽事件的，试玩时出现过「退租」排在「看房」前面，玩家反应是「这些人到底谁是谁」。随机换来的新鲜感，抵不上叙事断裂的代价。

### 同一个人反复出现

| 人 | 出现的地方 |
|---|---|
| 妈 | 第 1 天报平安、第 38 天要给你打钱、第 70 天问你过年回不回来 |
| 陈姐（中介） | 第 6 天带你去看「刚出的好房」、第 86 天让你帮着劝下一个客户 |
| 老周（二房东） | 第 9 天带你看房、第 12 天让你签租金贷、第 80 天退租扣押金 |
| 王主管 | 第 18 天面试不缴社保、第 30 天把你介绍去做外包 |
| 阿哲（老乡） | 第 46 天请你吃饭 |

同一个人在不同阶段身份会变：老周先老实告诉你水压小，后面照样拿租金贷。这不是人设崩了，是这类人的真实样子。第一条线的结尾，陈姐让你替她说当年别人对你说过的话。

### 旁白会认你的选择

`order` 里的 `bridge_if` 让旁白按标记分叉：

- 签过租金贷 → 第 54 天旁白变成「那份分期这周上了征信」，电话打来才不突兀
- 没签 → 旁白是「你在手机上搜过一次征信花了怎么办」

十五步里有两处这样的分叉，都在诈骗电话之前。玩家走的路不同，衔接的话也不同。

### 玩家也可以自己说话

选项只是最短的路。玩家可以不理选项，直接打字，模型照常接。开拍之前没人知道你会说什么，这一条不能写死。

结算要认得出自由输入。每种行动在数据里对应一个意图（例如「要求书面写清扣款理由」），玩家打的字先交给模型，归到最近的那个意图上，再按那个意图加减数值。判成完全不相干的，按没选处理。

## 6. 数据设计

`events.json` 里一条事件的结构：

| 字段 | 说明 |
|---|---|
| id / scene / title | 标识与展示 |
| type | black 黑心 / good 良心 / neutral 中性 / scam 骗子 / family 家人 |
| opponent | 对面是谁，和 `story.json` 的联系人对应 |
| goal | 对手想要什么，写进提示词 |
| opening | 开场第一句 |
| beats | 五拍走向，每拍一句「这一轮他要干什么」 |
| pits | 这一场埋的坑 |
| actions | 玩家能做的事，带数值增减、状态标记，以及 `pit` / `good` 判定 |

**beats 里没有台词。** 这是整个设计的关键，见第 7 节。

## 7. AI 设计

### 剧本只写意图，台词现场生成

数据里没有一句完整的台词。`opening` 写的是「他想让对方明白什么」，`beats` 写的是「这一轮他要干什么」。角色具体怎么说，由模型当场决定。

同一关开三次，开场三句都不同：

```
① 哎你来得正好，这房今天一早刚挂出来。
② 哎你来得正好，这房今早刚挂出来，看的人还不多。
③ 哎哟来得正巧，这房今早才挂出来，你运气是真好。
```

开头那句如果是固定的，玩家第二遍就会背下来，人物也变成念稿。顺序和时间轴写死是为了叙事不断，话写死就什么都没了。


### 每轮只给一个节拍

模型每次只收到：

1. 你是谁（一句人设，加上微信/电话的语境）
2. 你这一轮要干什么（beats 里的一句）
3. 规则（短句、不解释、不一次说穿、不提真实公司、不写旁白）
4. 玩家刚说的那句话

好处有三个：

- **不跑题。** 每一轮都有明确的戏，模型不会自由发挥到收不回来。
- **不一次演完。** 五拍就是五轮，节奏由代码控制。
- **可测。** 玩家走到第几拍、选了什么，日志里全部可见。

### 兜底

`fallback.json` 里每个事件备了五条台词，按拍索引取。模型调用失败（断网、额度、格式异常）就静默切换，页面上不报错。

答辩时可以现场断网演示，游戏照常可玩。

## 8. 关键取舍：为什么不让模型写剧情

最初的方案是让模型生成整个人生线，评估之后否掉了，理由是四条：

1. **它记不住。** 九十天、十五个事件、几万字上下文，模型会忘掉玩家还有多少钱。
2. **它不可复现。** 比赛要录视频、要写测试用例，每次都不一样就没法测。
3. **它不认节奏。** 模型不知道什么时候该推进，可能第三轮就把大结局放出来。
4. **它贵。** 每推进一个节点都调一次，一局几十次调用。

最终方案是**规则管全局，模型管局部**：事件、顺序、节拍、数值、结局全部由代码决定；模型只负责「这个人这一轮怎么说话」。

## 9. 数值与结局

| 数值 | 初始 | 作用 |
|---|---|---|
| money | 8000 | 钱 |
| trust | 50 | 和人之间的信任，影响结局与复盘口吻 |
| alert | 50 | 警惕，主要评分项 |
| blackout | 0 | 变成他们，只影响隐藏结局 |
| kept | 0 | 「这句话记下了」的次数 |

结局判定顺序固定：海外 → 你成了他们 → 租金贷 → 安家 → 回家。前面命中就不看后面。

## 10. 测试

| 项目 | 方法 | 结果 |
|---|---|---|
| 剧本自检 | `python test_flow.py` 开头的检查 | 通过：15 步，日期递增，人物与事件全对得上 |
| 接口可用 | `python test_client.py` | 通过：meta / talk / settle / review 全部 200 |
| 结算判定 | `test_client.py` 里好选择与踩坑各打一次 | 通过：good 与 pit 分别命中，`loan_signed` 标记写入 |
| 结局判定 | 构造五组数值各跑一次 | 通过：海外、你成了他们、租金贷、安家、回家都判对 |
| 自由打字 | 关卡里连打五句自己的话 | 通过：模型逐句接上，结算按最近选项判（显示「按……结算」） |
| 台词是否现场生成 | 同一事件连开三次场、同一句话回三次 | 通过：三次开场三句不同，回话不复读 |
| 端到端 | `python test_flow.py` 走完 15 步 | 通过：走到「你成了他们」，钱 9800，踩坑 3 次 |
| 界面流程 | 无头浏览器（CDP）点完一局 | 通过：通知条、会话、聊天、来电、结局全走通，无脚本报错 |
| 断网兜底 | 拔网线后再玩一局 | （待填） |
| 试玩 | 找 8 到 10 个人各玩一局 | （待填：平均时长、最常见的结局、卡住的地方） |

试玩时记三件事：**玩到第几个事件开始困**、**哪句话让人觉得假**、**结局猜到没有**。

## 11. 已知限制

- 没有账号系统，刷新即重来。
- 剧情顺序固定，重复玩的差异来自选择，不来自事件抽换。要更多变化得靠扩充事件池。
- 模型偶尔会说出和场景不符的话，尤其在没有上下文的第一轮。
- 只做了竖屏适配，桌面浏览器上是手机外框的居中展示。
- 不涉及真实个案，所有人物和机构均为虚构。

## 12. 运行与部署

```bash

python server.py                 # 默认 8000
```

接模型：把 `DEEPSEEK_API_KEY` 放进环境变量，见 README。

如果要在线演示，可以部署到任意支持 Python 的平台，注意 key 走环境变量，不要进前端。
